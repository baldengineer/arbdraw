ArbDraw JSON format

ArbDraw project files are UTF-8 JSON documents, normally saved with the .arbdraw.json extension. They describe one waveform, its instrument metadata, and its ordered voltage samples.

File identity

A compatible file must contain these values:

{
  "schema": "arbdraw.waveform",
  "version": 1
}

The top-level name is optional. Unknown top-level fields are ignored.

Basic structure

{
  "schema": "arbdraw.waveform",
  "version": 1,
  "name": "One Cycle Example",
  "waveform": {
    "type": "sine",
    "highVoltage": 1,
    "lowVoltage": -1,
    "sampleRateMSa": 0.001,
    "frequencyHz": 125,
    "cycles": 1,
    "phaseDegrees": 0,
    "dutyCyclePercent": 50,
    "sampleCount": 8,
    "values": [0, 0.7818314825, 0.9749279122, 0.4338837391,
      -0.4338837391, -0.9749279122, -0.7818314825, 0]
  }
}

Waveform fields

FieldUnitMeaning
type—custom, sine, square, triangle, ramp, pulse, dc, noise, or serial.
highVoltage, lowVoltageVNominal waveform levels.
sampleRateMSaMSa/sSamples per second in millions. 1 means 1,000,000 samples/second.
frequencyHzHzNominal waveform frequency metadata.
cyclescyclesNumber of waveform cycles represented by the samples.
phaseDegreesdegreesNominal phase offset.
dutyCyclePercent%High-state percentage for square and pulse waveforms, from 1 through 99.
sampleCountsamplesMust match the length of values; minimum is 2.
valuesVOrdered voltage samples. Every entry must be a finite JSON number.

UI prefixes such as mV, kHz, and µs are display choices. Project JSON always uses the canonical units above.

Authoritative and derived values

The sample data and timing metadata are authoritative: sampleCount, sampleRateMSa, frequencyHz, cycles, and values. ArbDraw recalculates durationMs when importing:

durationMs = sampleCount / (sampleRateMSa × 1000)

Frequency is metadata for the displayed waveform timing; it does not change the values stored in the sample array.

Serial waveforms

When type is serial, the optional serial object stores protocol and framing settings:

"serial": {
  "protocol": "UART",
  "baud": 57600,
  "wordSize": 8,
  "bitOrder": "LSB",
  "invertData": false,
  "parity": "none",
  "startBit": true,
  "preIdleBits": 1,
  "postIdleBits": 10,
  "stopBits": 1,
  "payload": "Hello World",
  "binaryPattern": ""
}

binaryPattern, when nonempty, overrides the generated serial bit sequence. Serial settings remain in the document even when another waveform type is selected so they can be restored later.

Import validation

  • schema, version, and waveform must be valid.
  • Numeric metadata may be supplied as numbers or numeric strings and is normalized on import.
  • sampleCount and cycles are rounded and clamped to valid minimums.
  • values must contain exactly sampleCount finite numbers.
  • If sample validation fails, ArbDraw discards the values and regenerates samples from metadata.
  • Unknown fields are ignored.

JSON cannot represent NaN or infinity. Do not write those values into values.

Writing compatible files

  1. Use UTF-8 JSON with schema set to arbdraw.waveform and version set to 1.
  2. Use volts, hertz, degrees, milliseconds, and MSa/s in metadata.
  3. Set sampleCount to the exact number of entries in values.
  4. Preserve fields you do not modify when reading and writing a project.
